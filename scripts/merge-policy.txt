# mgx 跟 tgx-android/telegram-x 合併時的取捨政策表（唯一真相來源）
#
# 目的：讓「跟隨上游」變成可機驗的規則，而不是每次合併都靠人肉回憶。
# 檢查器：scripts/check-merge-policy.sh（合併後必跑，不符就 exit 非 0）
# CI 掛點：.github/workflows/java-check.yml 與 .github/workflows/build.yml 的
#          「Verify merge policy」步驟（checkout 之後、編譯之前，純離線、秒級）
#
# 語法：每行一條，欄位用 | 分隔，共 5 欄，順序固定：
#   kind | path | expected | bad_value | note
# kind 取值：
#   deleted    path 這個路徑必須「不存在」於 git ls-files（上游刪掉的東西不准被合併帶回來）
#   deleted-any  path 欄當「子串」比對，任何追蹤路徑含該子串就算違規（整棵目錄用）
#   present    path 必須仍然存在於 git ls-files（被誤認為遺物、實際還在用的東西）
#   gitlink    path 的子模組 pin 必須等於 expected；等於 bad_value 會另報「退回舊值」
#   branch     .gitmodules 中該 path 對應 submodule 段的 branch 必須等於 expected
#   nobranch   .gitmodules 中該 path 對應段必須「沒有」branch 欄位（釘死在 tag 或上游無分支）
#   prop       path=檔案、expected=檔內必須出現的一行、bad=必須不出現（可逗号分隔）
# 規則：空行與 # 開頭忽略；note 是給人看的，不得含 |；腳色欄值不得含空白。
#
# 合併流程（跟 tgx 合併時照這走，衝突就不用人肉重解）：
#   1) 本倉已開 git config rerere.enabled=true 與 rerere.autoupdate=true，
#      同一個衝突第二次會自動套用第一次的解法並直接標記 resolved。
#   2) 第一次遇到新衝突時，照本表的 kind 決定方向：deleted/present 維持我方存在性、
#      gitlink 一律取 expected、branch 一律取 expected；解完 git add 讓 rerere 記下來。
#   3) 合併收尾跑 scripts/check-merge-policy.sh（CI 也會跑），非 0 就別推。
#   4) 本表改了要連 gitlink／.gitmodules／version.properties／libs.versions.toml 一起改，
#      同一個版號常藏兩到三處，只改一半等於沒改。
